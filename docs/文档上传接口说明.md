# 文档上传接口说明（RAG 入库）

新增两个上传接口：

1. `POST /memory/upload/file`：单文件上传并写入 RAG 向量库。
2. `POST /memory/upload/folder`：从服务端本地文件夹批量读取文档并写入 RAG 向量库。

## 支持格式


- FastAPI 文件上传接口依赖 `python-multipart`，若未安装会在应用启动时报错。

- `.txt`
- `.pdf`
- `.doc`
- `.docx`

> 说明：
> - `.pdf` 解析依赖 `pypdf`
> - `.docx` 解析依赖 `python-docx`
> - `.doc` 解析依赖 `textract`

## 1) 单文件上传

### 请求

`multipart/form-data`

- `file`: 文件（二进制）
- `user_id`: 用户/会话 ID（默认 `id`）
- `role`: 角色（默认 `user`）
- `tags`: 逗号分隔标签（可选）

### 返回

- `status`: success/fail
- `file`: 文件名
- `chunks`: 切分后的文本块数量
- `message`: 结果说明

## 2) 文件夹批量上传

### 请求

`multipart/form-data`

- `folder_path`: 服务端可访问目录路径（必填）
- `user_id`: 用户/会话 ID（默认 `id`）
- `role`: 角色（默认 `user`）
- `tags`: 逗号分隔标签（可选）

### 返回

- `files_total`: 识别出的可解析文件数量
- `files_success`: 成功入库文件数
- `chunks_total`: 总入库分块数
- `failed`: 失败文件与原因

## 入库策略

- 文档文本会进行标准化并按固定窗口切分（默认 `chunk_size=800`, `overlap=120`）。
- 每个 chunk 调用现有 `qdrant_service.add_memory` 写入向量库。
- 自动附加原文件名到 tags，便于后续追溯。

- 新增去重策略：上传流程会对 chunk 文本计算哈希，过滤同次上传重复内容，并在入库前做数据库侧重复检查，避免重复数据写入。


## Windows / Linux 依赖差异说明

- `.doc` 解析依赖 `textract`，其依赖链在 Windows 中常见 `fcntl` 缺失问题（`fcntl` 为 Unix-only）。
- 因此项目已做平台分流：
  - Linux/macOS：支持 `.doc`（需安装 `textract`）。
  - Windows：调用 `.doc` 解析会返回明确错误，建议先转为 `.docx` 或 `.txt`。
- `pyproject.toml` 已将 `textract` 设为 `sys_platform != 'win32'` 条件依赖，避免 Windows 安装阶段失败。
